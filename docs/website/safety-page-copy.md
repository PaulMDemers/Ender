# Ender Safety & Control Page Copy Deck

This document provides implementation-ready copy for the Safety & Control page.

---

## Page Goal

Explain that Ender is designed for supervised operation and that human oversight is a core product strength.

A visitor should understand that:
- Ender supports approval-gated actions
- Ender provides live visibility into execution
- Ender persists thread history
- Ender is built to keep humans in the loop for impactful actions

---

## Hero Section

### Heading
- **Human-in-the-loop by design**

### Subheading

Ender is built for supervised agent work. It keeps execution visible, preserves operational history, and can pause for approval before sensitive actions happen.

---

## Overview Section

### Heading
- **Safety through visibility and control**

### Body copy

Ender does not treat agent execution as a black box. Operators can watch live logs, inspect task progress, review pending actions, and approve sensitive steps before they happen.

This is a core part of the product model, not an optional add-on.

---

## Approval Model Section

### Heading
- **Approval-gated actions**

### Body copy

When an action has external or persistent consequences, Ender can pause and request operator approval. This helps teams use powerful tools without giving up control over impactful changes.

### Example actions to list
- risky shell commands
- git push
- pull request creation
- merge request creation
- Jira transitions and comments
- Confluence page creation and updates
- Google Drive uploads and updates
- email sending
- schedule creation or deletion where configured
- self-update apply

### Supporting statement

Approval gates should be framed as a product strength: Ender is designed to make powerful actions usable in supervised environments.

---

## Live Supervision Section

### Heading
- **Live supervision**

### Body copy

Ender streams task logs and transcript updates so operators can see what is happening while work is in progress. This makes it easier to understand task behavior, review tool usage, and intervene when needed.

---

## Persistent History Section

### Heading
- **Persistent thread history**

### Body copy

Threads persist on disk, which means work can be resumed later and operational history is not lost when a session ends. This is important for real tasks that span multiple sessions, approvals, or follow-up actions.

---

## Local-First Control Section

### Heading
- **Local-first control model**

### Body copy

Because Ender is local-first, operators and teams can run it in environments they control. This supports a more practical and trustworthy operating model than a purely opaque hosted system.

---

## Why This Matters Section

### Heading
- **Why this matters for real teams**

### Body copy

The more capable an agent becomes, the more important supervision becomes. Ender is designed for teams that want real tool access, automation, and operational reach without giving up visibility or approval control.

---

## Closing CTA Section

### Copy

Ender is built for teams that want supervised agent operations, not blind autonomy.
