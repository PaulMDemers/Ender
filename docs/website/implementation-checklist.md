# Ender Website Implementation Checklist

This checklist is for the next LLM or implementation agent rebuilding the site.

---

## Positioning Checklist

- [ ] The site clearly states that Ender is a local-first agent runtime.
- [ ] The site clearly states that Ender is operator-facing.
- [ ] The site clearly communicates supervised execution and approvals.
- [ ] The site does not read like a generic chatbot landing page.
- [ ] The site does not imply unsupported hosted SaaS behavior.

---

## Homepage Checklist

- [ ] The homepage hero explains Ender in one screen.
- [ ] The homepage mentions local-first runtime.
- [ ] The homepage mentions approvals.
- [ ] The homepage mentions workflows.
- [ ] The homepage mentions schedules.
- [ ] The homepage mentions persistence.
- [ ] The homepage mentions browser UI and desktop app.
- [ ] The homepage includes concrete tool ecosystem language.
- [ ] The homepage includes real screenshots.

---

## Page Coverage Checklist

- [ ] Product page exists.
- [ ] Tools overview page exists.
- [ ] Tool category pages or equivalent sections exist.
- [ ] Workflows page exists.
- [ ] Automation page exists.
- [ ] Safety page exists.
- [ ] Architecture page exists.
- [ ] Docs / Getting Started page exists.
- [ ] Compare page exists.
- [ ] Contact page exists.

---

## Tools Coverage Checklist

- [ ] Workspace & Files is covered.
- [ ] Shell & Local Execution is covered.
- [ ] Web & Browser is covered.
- [ ] Git & Repositories is covered.
- [ ] GitHub & GitLab is covered.
- [ ] Jira & Knowledge Systems is covered.
- [ ] Email & Communication is covered.
- [ ] Scheduling & Delegation is covered.
- [ ] Self-Update is covered.

---

## Product Truth Checklist

- [ ] The site mentions the current built-in workflow `jira_to_repo_task`.
- [ ] The site does not imply a large built-in workflow catalog unless that becomes true.
- [ ] The site explains that Ender supports OpenAI, Bedrock, Azure OpenAI, and Ollama.
- [ ] The site explains that Ender persists threads, schedules, and workflow sessions.
- [ ] The site explains that Ender exposes a local API.

---

## Safety and Control Checklist

- [ ] Approval-gated actions are explained clearly.
- [ ] Live logs or live supervision are explained clearly.
- [ ] Persistent thread history is explained clearly.
- [ ] Human-in-the-loop positioning is treated as a strength.

---

## Visual Checklist

- [ ] Main task thread screenshot is included.
- [ ] Approval UI screenshot is included.
- [ ] Workflow UI screenshot is included.
- [ ] Schedule UI screenshot is included.
- [ ] Desktop app screenshot is included.
- [ ] Visuals use real product states where possible.

---

## Linking Checklist

- [ ] The site links to docs.
- [ ] The site links to GitHub.
- [ ] The site links from homepage to tools/workflows/automation/safety pages.
- [ ] Tool pages link to related docs or deeper references where appropriate.

---

## Final Quality Checklist

- [ ] The site is concrete rather than hype-driven.
- [ ] The site communicates Ender’s true strengths and current abilities.
- [ ] The site avoids unsupported claims.
- [ ] Another technical visitor could understand the product quickly and accurately.
