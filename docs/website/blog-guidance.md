# Ender Blog Guidance

This document provides guidance for future blog content so it stays aligned with the actual product.

---

## Goal

The blog should reinforce Ender’s real strengths and avoid drifting into vague conceptual AI commentary disconnected from the product.

---

## Core Themes to Emphasize

- supervised agent operations
- local-first agent infrastructure
- approval gates as a product feature
- workflows versus freeform prompting
- recurring automation with visibility
- practical tool ecosystems for agents
- durable operational state and persistent threads

---

## Product Truth to Keep Visible

Future posts should regularly tie ideas back to concrete product realities:

- local-first runtime
- browser UI and Electron desktop app
- local API
- persistent threads, schedules, and workflow sessions
- guided workflows
- cron-backed schedules
- approval-gated actions
- broad tool ecosystem
- multiple model backends

---

## Good Post Types

- product announcement updates grounded in shipped features
- deep dives on workflows
- deep dives on schedules and automation
- why approval gates matter in real operations
- local-first deployment as an operational advantage
- tool ecosystem spotlights
- architecture explainers for technical evaluators

---

## Avoid

- vague “AI is changing everything” posts with little product relevance
- claims that imply unsupported capabilities
- language that suggests Ender is a fully autonomous replacement for teams
- generic thought leadership that does not connect back to the actual runtime

---

## Suggested Reusable Framing

Ender is built for real work in real environments. That means supervision, durable state, practical tool access, and structured operational flows matter as much as model quality.

---

## Notes for the Implementer

- Keep posts concrete.
- Use screenshots or product references where possible.
- Link to docs, tools pages, workflows pages, and architecture pages when relevant.
